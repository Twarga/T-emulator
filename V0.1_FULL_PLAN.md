# T-EMULATOR — v0.1 FULL PLAN
*The complete build document for version 0.1: PSP + XMB, end to end.*

**Version goal:** launch the app → see console picker → power on "PSP" → watch its coldboot → land on a living XMB menu → scroll your games → pick one → it plays fullscreen via PPSSPP → quit → back on the wave → Esc → picker.

**Division of labor:** I write all code on tlab (SSH, headless, 8c/30G). You only run test binaries on your laptop and report pass/fail.

---

## 1. Scope (frozen)

### In v0.1
- **One console:** PSP only (others shown as locked cards in picker)
- **One skin:** XMB (PSP flavor) — fullscreen, borderless
- **One backend:** PPSSPP — downloaded automatically, configured once, launched headless
- **One games flow:** scan `~/Games/PSP` → tiles on XMB → launch → return
- **One wizard:** first run only — welcome → games folder → done
- **Inputs:** keyboard (arrows/enter/esc) + one gamepad (dpad + confirm/back)
- **Persistence:** `config.toml` in `~/.config/t-emulator/` (games dir, prefs)

### Explicitly NOT in v0.1
No covers/metadata · no manager pages · no updates UI · no controller remapping · no save manager · no per-game profiles · no other consoles · no store · no themes.

---

## 2. Why these choices

| Choice | Reason |
|---|---|
| **PSP first** | PPSSPP needs NO firmware file → true zero-setup; most mature emulator; fewest edge cases |
| **XMB** | Same skin serves PSP + PS3 later — highest reuse; most iconic console UI; the visual product |
| **PPSSPP** | `ppsspp <game>` accepts a file path and goes fullscreen — headless-enough for v0.1 |
| **Slint** | Native GPU UI, no webview, small binaries, strong animation API — the "not shitty slop" requirement |
| **Rust** | Speed, single binary deploy to laptop, matches emulator-manager work |
| **Adapters, not forks** | Emulators stay stock; we only download + configure + launch them |

### Adapter contract (v0.1 shape — PSP only implements it now)

```rust
pub trait EmulatorAdapter {
    fn is_installed(&self) -> bool;
    fn install(&self, progress: impl Fn(f32)) -> Result<()>;   // fetch official release
    fn write_defaults(&self, hw: &HwProfile) -> Result<()>;    // ini once
    fn launch(&self, game: &Path) -> Result<Child>;            // spawn, return child
    fn supports(&self, file: &Path) -> bool;                   // .iso/.cso/.pbp
}
```

### Two window modes, one binary
- `t-emulator` → windowed manager (picker + wizard)
- Selecting a console **re-renders the same process fullscreen** into the skin (no subprocess for the UI itself). Simpler than two binaries; Slint handles window mode change.
- On `play_game` → spawn `ppsspp <game>` child → Slint hides/minimizes → on child exit → restore XMB.

## 4. UI spec for v0.1 (subset of UI_SPEC.md, binding)

**Tokens:** bg `#0e0e14`, surface `#16161f`, text `#e8e8f0`, dim `#8a8a9e`, accent-xmb `#4ea8ff`, radius 10px, font Inter 13–14 body / 24 picker titles, transitions 250ms ease-out.

**Picker:** horizontal card strip centered; focused card at 1.0 scale + accent glow + lift; neighbors 0.85 + 40% dim; PSP card enabled, PS3/GC/PS2 greyed `Soon`. Bottom hint bar: `Ⓐ power on · arrows move`.

**XMB skin:**
- `WaveBg`: 3 sine ribbons (ported math from OpenXMB/xmb-web — see §6), continuous drift, monthly hue shift baked to accent-xmb, subtle grain optional
- Category row: `Settings · Games · Network` (only Games populated v0.1; others show empty-state row "Nothing here yet")
- Focused category centers; items list vertically under it
- Game item: icon + title; focused → scale 1.06 + InfoPanel slides in right (title, size, last played=stub "—")
- Clock `HH:MM` + `Day DD Mon` top-right, live
- Boot splash: fade from black → coldboot anim ~1.2s → wave fades in; any input skips
- Sounds: `tick` on move, `select` on confirm, `back` on back

**Input map:** dpad/leftstick = move · Cross/A or Enter = confirm · Circle/B or Esc = back · hold Circle on root = exit to picker.

## 6. Technical notes (the hard parts)

**The Wave** — the make-or-break asset. Implementation: 3 parametric sine-ribbon paths, recomputed per frame (Slint `Path` or custom `Painted` item via `slint::PaintCallback` on wgpu). Port parameters from OpenXMB (`src/` wave code) and xmb-web (exact amplitudes/phases/gradients). Verify visually side-by-side.

**PPSSPP launch details:** binary `PPSSPPSDL`/`PPSSPPQt` inside AppImage → extract or run `--appimage-extract-and-run`. Launch args: `--fullscreen <path>`. Config at `~/.config/ppsspp/PSP/SYSTEM/ppsspp.ini` — write `[Graphics] RenderingMode=Vulkan`, `InternalResolution=2`, `FullscreenOn=true` (verify exact keys against shipped ini on first launch — PPSSPP writes a default ini we patch, not author from scratch).

**Wayland risk:** gilrs events under fullscreen Slint on GNOME/Wayland — verify Phase 0. Fallback: document X11 session or `SLINT_BACKEND=winit`.

**File formats scanned:** `.iso`, `.cso`, `.pbp`, `PSP/GAME` dirs → each becomes a tile.

**Config file:** `~/.config/t-emulator/config.toml` — `games_dirs = { psp = "..." }`, `last_console`, `volume`, `animations = true`.
